# Offline voice typing

AlphaDocs uses a native CPAL/Vosk speech sidecar, built with the optional `speech-worker` Cargo feature. The normal app does not link microphone or recognition libraries and can launch without a language model. The microphone opens only after the user presses Start. Audio is decoded locally; no audio or document text is uploaded.

First-use setup is explicit. It downloads the official Vosk API 0.3.42 runtime directly from its upstream GitHub release and the small English (United States) 0.15 model from Alpha Cephei. Setup verifies exact archive sizes and SHA-256 hashes, rejects unsafe paths/symlinks and bounds extraction. Downloads are approximately 54.3 MB on Windows x64, 48.4 MB on Linux x64 and 45.9 MB on either Mac architecture. Nothing downloads at startup or merely by opening Voice typing. Cancellation keeps the document unchanged. The model/runtime live in the platform application-data `speech` folder, outside the installer and repository.

The installer contains the native sidecar, rather than redistributing the upstream runtime DLLs. Setup places a copy of the tested sidecar beside the verified runtime for loader-relative library resolution. An app-version or worker-hash change requires explicit setup again. Existing runtime caches are retained when repaired/replaced. The Windows runtime contains GCC/MinGW libraries with their own terms; notices are included separately and must not be described as covered by Vosk's Apache licence.

The current UI supports English (United States). It shows microphone Start/Stop, input level, partial transcript preview, cancel and setup progress. Stop and insert commits a final transcript through Editor as one undoable operation. Moving the caret, editing, switching document/content tab, entering read-only mode, opening a blocking workspace or closing the panel discards a running preview. Punctuation/formatting voice commands and automatic language switching are not implemented. Recognition accuracy depends on voice, microphone and noise; no comparison with commercial cloud dictation is claimed.

The sidecar and editor communicate over bounded, versioned NDJSON, with session IDs. Only a final `stopped` event is eligible for insertion after document/tab/revision/selection/read-only revalidation. Preview text never mutates a document. Audio conversion downmixes supported PCM input and resamples to 16 kHz across callback boundaries. Runtime workers run without flashing console windows. Tests never capture a real microphone or automate privacy permissions.

Builds use `scripts/prepare_speech.py --prepare-native` to fetch pinned host libraries for linking/testing, then separately build `alphadocs-speech`. `--stage` adds only that sidecar to dist. Windows x64, Linux x64 and Intel/Apple Silicon macOS are the supported package targets. CI compilation/package checks are not physical microphone verification. A synthetic WAV diagnostic exercises recognition without microphone access; native-device microphone/permission checks remain human tests.

Photon was researched but is not included in this release. Its Python dependency/runtime download and platform constraints were unnecessary for the chosen compact offline workflow. No Photon packages or Python runtime are installed by AlphaDocs.
